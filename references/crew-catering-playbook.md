# 团餐实战手册

## 典型触发语句

- 「班组 12 个人加班，订个麦当劳，人均 30 左右」
- 「明天中午给项目部订团餐，20 人，预算 800」
- 「十几个人夜班加餐，帮我配几套方案对比」
- 「这个门店团餐有什么助餐服务」

## 预算算法

1. 拿到人数 `N` 与人均预算 `B`（元），得出总预算 `T = N × B`。
2. 按官方预算带选定搭配结构，从菜单中挑出该档位可组合的商品。
3. 份数规则：按人数取份，饮料与小食可整份取整，避免拆单。
4. 计价后计算人均实付 `P = 实付总价 / N`，与 `B` 比对，超出则降档重算。
5. 输出三套方案：
   - **方案 A 省钱档** — 卡在预算下限，优先用券
   - **方案 B 均衡档** — 人均最接近预算，推荐项通常在此
   - **方案 C 加料档** — 略超预算，配置更丰富

三套方案必须能直接对比，字段一致：门店、构成、单份价、份数、优惠、配送费、总价、人均、与预算差额。

## 助餐服务

`query-meal-assistance` 仅在 `beType=6` 可用，返回该门店支持的助餐服务列表。取回后把服务项用人话讲给用户听，让用户选择，再把对应的 `gmServiceCode` 一路带到计价与下单。

这一步是本技能的核心差异点：绝大多数麦当劳 MCP 项目只做省钱凑单或营养计算，不会碰团餐助餐服务。

### 实测三档服务（2026-10-12）

| gmServiceCode | 名称 | 服务内容 | 可用性 |
|---|---|---|---|
| `GMS001` | 保鲜速达 | 准时送达 & 餐品保温 | 默认选中，始终可选 |
| `GMS002` | 专人分餐 | 准时送达 & 餐品保温、送餐到桌/到人 | 仅送达时间在 07:00–20:00 的订单可选 |
| `GMS003` | 专人摆台 | 准时送达 & 餐品保温、餐品摆台、专人服务 | 仅送达时间在 07:00–20:00 的订单可选 |

接口返回 `enable` 与 `unusableReason` 两个字段。当 `enable=false` 时，直接把 `unusableReason` 告知用户，并给出可享时段，让用户改时间或降档到 `GMS001`，不要静默替用户选。

**推论**：夜班加餐（20:00 之后送达）只能用到保鲜速达，专人分餐与摆台用不了。订夜班餐时不必推荐专人服务。

## 菜单返回结构

`query-meals` 返回两部分：`categories`（分类 → 商品编码列表 + 标签）与 `meals`（编码 → 商品详情映射，含 `name`、`currentPrice`、`originalPrice`、`canWithOrder`）。

搭配时先从 `categories` 定位分类，再用编码去 `meals` 取名称与价格。菜单里的 `currentPrice` 单位为**元**（与 `calculate-price` 返回的分不同，注意区分）。

## 优惠券策略

1. `available-coupons` 先看有什么可领。
2. `auto-bind-coupons` 一键全领（幂等，重复调用安全）。
3. `query-my-coupons` 确认到账，挑出对当前商品组合生效的券。
4. 计价时把 `couponId` 与 `couponCode` 一并传给 `calculate-price`。

若领券后计价无变化，说明券不适用于该组合，如实说明，不要谎称已优惠。

## 实战话术

**收集信息**（一次只问一项）：
> 人数和人均预算分别多少？我先按这两项配三套方案。

**输出方案**：
> 按 12 人、人均 30 元配了三套，均衡档（方案 B）最贴合预算，人均实付 29.4 元。要下单的话我再走确认。

**确认闸门**（缺一不可）：
> 下单前确认一遍：XX 门店，XX 套餐 ×12，已用 XX 券，总价 XXX 元，人均 XX 元，配送到 XX 地址，XX 时间送达。确认下单吗？

**支付引导**：
> 订单已创建，用这个链接或麦当劳 APP 完成支付。付完回我一句「支付完成」，我帮你查最新状态。

## 踩坑记录

| 坑 | 表现 | 解法 |
|---|---|---|
| 请求头缺 `Bearer ` 前缀 | 界面提示「需要验证」，服务端判 Token 无效 | 写成 `Bearer <token>`，中间一个空格 |
| 用了旧路径 | 连不上 | url 只能是 `https://mcp.mcd.cn` |
| 批量拉菜单被限流 | 返回 429 | 加调用间隔，勿当作 Token 失效 |
| 改了配置不生效 | 仍报鉴权失败 | 在 WorkBuddy 里关掉再开启连接器，或重启应用 |
| 团餐计价失败 | 报参数错误 | 检查 `gmServiceCode` 是否带上 |
| 把价格当元展示 | 数字大了一百倍 | 单位是分，除以 100 |

## 安全红线

- Token 等同麦当劳账户钥匙，能领券能下单。不写进代码、README、Issue、任何公开仓库。
- 配置文件只用环境变量占位符，如 `MCD_MCP_TOKEN`。
- 未经用户明确确认，绝不调用 `create-order`。
